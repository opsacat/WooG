# WoG 宝玉助手 · 代码体检与维护路线图

> 接管自 `dooooongyuan/WooG`（作者已停更）。本仓库为 fork：`opsacat/WooG`。
> 体检日期：2026-10-27。结论：**代码底子扎实，可放心长期维护**，但有若干"游戏版本耦合"带来的持续性维护成本需要提前规划。

## 一、总体结论

| 维度 | 评价 | 说明 |
| --- | --- | --- |
| 许可 | ✅ Apache 2.0 | 可自由 fork/修改/再发布，只需保留版权与许可证声明 |
| 代码结构 | ✅ 分层清晰 | 游戏接口层（`宝玉助手.py`）与 UI（`宝玉面板.py`）分离，所有游戏内 JS 集中一处，无两份实现漂移 |
| 健壮性 | ✅ 高 | 双连接回退（CDP WebSocket + Frida）、配置校验/原子写/备份、补丁 SHA256 校验、凭据不入库 |
| 测试 | ⚠️ 部分 | server + 补丁 15 个测试全过；panel 逻辑测试 1391 行但需 GUI 环境，尚未在 CI 跑 |
| 可维护性 | ⚠️ 中等 | 面板单文件 4832 行（"上帝文件"），依赖声明不全，缺版本/CHANGELOG/CI |
| 版本耦合风险 | 🔴 高 | 强依赖游戏内部 `nn.*` 对象与特定 `GameAssembly.dll` 哈希，每次游戏更新都可能要跟进 |

**一句话：能接，且值得接。最贵的不是写代码，而是每次 WoG 大版本更新后重做"补丁偏移 + 逆向接口"的校验。**

## 三、代码质量亮点（保持不变，顺着写）

1. **单一 JS 真源**：`宝玉助手.py` 里所有游戏内 JS 都集中定义，面板只 `import` 后拼参调用，杜绝"两份逻辑各自漂移"。这是后续维护最大的安全垫。
2. **连接韧性**：`Game.eval` 用请求锁保证多线程下不互相吞回复；WS 不可用时回退 Frida，且 `close()` 对两种模式都做了清理。
3. **配置安全**：`_sanitize` 把字符串 `"false"` 不当真、`_atomic_config_write` 用 PID+线程号临时文件防并发、`save_config` 先写 `.bak` 再落盘。
4. **补丁工具克制**：`assert_game_stopped` 先确认游戏退出、`assert_current` 校验 DLL 的 SHA256、恢复时比对 manifest，避免把错的文件写回去。
5. **安全意识**：`.gitignore` 已排除 `*.token`、`steam-cookie`、`*.sqlite3`、配置与统计；价格服务只用 Bearer token，不转发上游错误。
6. **注释讲"为什么"**：例如明确写"旧实现用的 `getStorageTotal()` 游戏里不存在，一直退回硬编码 300"、"失败时游戏不清暂存，必须立刻 `clearFusionStaging`"——这些踩坑记录对继任者极有价值。

## 四、风险评估（按紧迫度排序）

### 🔴 R1 · 10998 补丁与游戏版本强绑定（最高优先级，持续性）
`tools/修复宝玉助手连接.py` 写死了：
- `TARGET_OFFSET = 16_934_718`
- `EXPECTED_CURRENT_SHA256 = "3f55a978..."`

WoG 每次更新 `GameAssembly.dll`，哈希必变，补丁会**按设计拒绝执行**（安全，但意味着助手连不上，直到有人重新定位偏移 + 重算 SHA256）。这是"一直更新"的真正工作量来源：**每个大版本都要重做这一步**。

> 建议：在 `docs/` 写一份"重算 10998 偏移与 SHA256 的流程说明"，把逆向下一版的步骤固定下来，别每次从头摸索。

### 🔴 R2 · 强依赖游戏内部 `nn.*` 对象（核心功能脆弱点）
`宝玉助手.py` 里的 `JS_HELPERS`、`STORAGE_INFO`、`ECONOMIC_SNAPSHOT`、`FUSE_FLOW` 等全部依赖逆向出来的 `nn.db` / `nn.services` / `nn.net.data` 字段（如 `nn.services.workshop.collectAutoRegisterCandidates`）。游戏更新改了对象名/字段，统计、合成、入库、整理会集体失效。

> 建议：把"逆向接口速查表"（每个 `nn.*` 字段的版本、含义、失效记录）沉淀进 `docs/`，降低每次修复的排查成本。

### 🟠 R3 · 依赖声明不全
`requirements.txt` 只有 `websocket-client>=1.7`，但：
- `psutil` 在 `宝玉助手.py:_find_game_pid` 被直接 `import`（无 Frida 回退时也会用到），**未声明**；
- `frida` 在回退路径被 `import`，**未声明也未标注为可选**；
- 价格服务用 `/usr/bin/curl`（**硬编码 Unix 路径**），Windows 上必然走 urllib 兜底分支——功能可用，但主路径对 Windows 玩家无效。

> 建议：补全 `requirements.txt`（`psutil` 必装、`frida` 标 optional）；价格服务做跨平台探测（有 curl 用 curl，否则 urllib）。

### 🟠 R4 · 面板单文件 4832 行（"上帝文件"）
`宝玉面板.py` 一个文件承载了所有自定义控件、`App` 主类、统计/经济/邮件/市场全部逻辑。可读、评审、合并冲突风险都高。拆分收益大但风险也大（`App` 内部状态高度交织）。

> 建议：不急于拆。先做低风险的"纯函数外提"（把统计归类、经济 delta、价格冷却等无状态逻辑抽到独立模块并补单测），再视情况按 `widgets / tabs / stores / market / mail` 拆文件。

### 🟡 R5 · 缺工程化基础设施
无 `pyproject.toml`、无 lint/类型检查、无 `CHANGELOG`、无版本号、无 tag、无 CI。对"长期维护 + 可能收社区贡献"的项目，这些是信任信号。

### 🟡 R6 · 中文文件名
`宝玉面板.py`、`宝玉助手.py`、配置示例均为中文名。Win/macOS 无碍，但个别 Linux 工具链/老旧脚本可能踩编码坑。属低优先度，仅提示。

## 五、维护路线图（建议节奏）

### 阶段 0 · 基础设施（可立即做，低风险）
- [ ] 补全 `requirements.txt`（`psutil` 必装；`frida` 标 optional）
- [ ] 加 `__version__`（如 `宝玉助手.py` 顶部）＋ `CHANGELOG.md`＋ 首个 `v0.1.0` tag
- [ ] 新增 `CONTRIBUTING.md`：开发环境、如何跑测试、如何重算 10998 偏移/SHA256
- [ ] 加 GitHub Actions：Linux 上跑 `tests.test_price_service` + `test_port_patch`（panel 测试需处理 headless Tk，可后续）

### 阶段 1 · 健壮性（中风险，按需）
- [ ] 价格服务跨平台探测 curl/urllib
- [ ] 把 Frida `bridge.js` 纳入仓库或文档化其外部来源（当前 `scripts/drop_interval_mod/bridge.js` 不在 repo，回退路径开箱即用不了）
- [ ] 外提面板纯函数并补单测（统计归类、经济 delta、价格冷却）
- [ ] （可选）面板按模块拆文件

### 阶段 2 · 社区与分发
- [ ] `docs/` 沉淀"逆向接口速查表"与"补丁重算流程"
- [ ] issue / PR 模板
- [ ] PyInstaller 打包出 release，方便普通玩家直接下载 exe

### 阶段 3 · 跟随游戏更新（长期，听你的痛点）
- [ ] 每次 WoG 大版本：重算 10998 偏移 + 更新 `EXPECTED_CURRENT_SHA256` + 校验 `nn.*` 接口
- [ ] 你游玩中遇到的功能痛点 → 新需求
